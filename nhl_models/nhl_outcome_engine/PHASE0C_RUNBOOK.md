# NHL Phase 0C — durable forward snapshot capture (runbook)

Hockey information only: no prediction, no model, no sportsbook data. Forward status stays **BLOCKER_INSUFFICIENT_LIVE_TIMING_EVIDENCE** until the registered sample exists (`phase0c_capture_protocol.json`).

**Execution:** `.github/workflows/nhl_forward_snapshot.yml` — cron every 15 min + `workflow_dispatch` (run / readiness / status / evaluate); concurrency group `nhl-forward-snapshot`, `cancel-in-progress: false`; stdlib-only Python; runs only `nhl_fwd_scheduler.py`. A scheduled workflow only fires from the default branch, so nothing runs before the deployment PR is merged.
**State:** orphan branch `nhl-forward-state` (created by the workflow on first run): `schedule_observations.jsonl`, `planned_keys.jsonl`, `endpoint_observations.jsonl`, `horizon_results.jsonl`, `postgame_truth.jsonl` (append-only), `blobs/<sha256>.gz` (identity = sha256 of the UNCOMPRESSED response; verified on every read; same sha + different bytes = hard error), and derived `status.json` / `readiness.json` / `evaluation.json`. A failed push fails the run (`::error::`).

**Timing (registered):** cutoff = scheduled_start − horizon for T24H/T90/T30/T10/T2; decision key = game_id|horizon|scheduled_start (a revised start creates a new key, old evidence immutable). The job may wake up to 20 min early and waits inside the job; capture starts 120 s before the cutoff; same-cutoff games are captured together (≤ 8 concurrent games). A horizon endpoint qualifies only if its request starts before the cutoff and completes in [cutoff − 180 s, cutoff]: earlier → `EARLY_NOT_HORIZON_EVIDENCE`, later → `MISSED_HORIZON_CUTOFF`, initiated at/after puck drop → `REFUSED`. Never backfilled, never relabelled. A game-horizon is `COMPLETE_VALID` only if all four endpoints (landing, right-rail, boxscore, play-by-play) are valid.
**Schedule provenance:** every key references the sha256 of the raw schedule response that established its start (stored as a blob) with its retrieval started/completed times.
**Postgame truth:** once per game, only when the boxscore is FINAL/OFF (`POSTGAME_TRUTH`, never a pregame feature): final dressed skaters/goalies, SOG by skater, team SOG.
**Evaluation / recommendation:** `evaluation.json` is produced only as `NOT_EVALUATED_INSUFFICIENT_SAMPLE` until ≥ 50 games with truth on ≥ 3 dates and ≥ 40 COMPLETE_VALID observations at the horizon; a horizon qualifies if `capture_success_rate` ≥ 0.99 (**protocol 2, PRE_LIVE_AMENDMENT_1**: COMPLETE_VALID eligible keys / ALL eligible non-revised keys; an eligible opportunity is a planned non-revised key whose game eventually has postgame truth and with `planned_at ≤ cutoff − WAKE_LEAD_SECONDS`; MISSED / PROVIDER_FAILURE / REFUSED / REJECTED_NOT_PREGAME_STATE / EARLY_NOT_HORIZON_EVIDENCE all count as failures; games enrolled later are `LATE_ENROLLMENT_NOT_ELIGIBLE`, reported and excluded; `games_attempted` is diagnostic only), final dressed skater recall ≥ 0.995 and final SOG coverage ≥ 0.995 (rosterSpots); the earliest qualifying horizon is recommended. Goalie starter confirmation is not part of this pass.
**Inspect:** `status.json`, `readiness.json`, `evaluation.json` on the state branch; `python nhl_fwd_scheduler.py status|readiness|evaluate --state <dir>` (readiness exits 2 when not ready).
**Manual recovery:** Actions → "NHL forward snapshot" → Run workflow (mode `readiness` first, then `run` with `duration_min` near a cutoff). A manual run cannot backdate: a cutoff reached without a compliant capture stays MISSED_HORIZON_CUTOFF.

**Right-rail scratch availability:** available iff the `scratches` field is present and a list for both teams (empty list = available with zero scratches; absent / non-list = unavailable).
**Concurrency:** each ledger carries an internal `threading.RLock` (read / append / the whole `append_unique` check-then-append); no lock is held across a network call.
**Amendment record:** `phase0c_capture_protocol.json` → `amendments[PRE_LIVE_AMENDMENT_1]`, registered before any compliant live evidence (base research commit `717bab9`). Capture timing, constants and thresholds are unchanged.
